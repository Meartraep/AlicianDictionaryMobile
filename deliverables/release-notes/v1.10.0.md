# Alician Dictionary v1.10.0

## 主要更新

- **手机端发布数据库**：在手机上直接把本地数据库发布为新版本。App 读取已发布台账取得下一个版本号，把它写进数据库副本、追加 `database-versions.json`、重写 `database-manifest.json`，一次提交这三个文件并开 PR；CI 只做校验（改动文件白名单、版本号必须正好是下一个、sha1／大小／库内 marker／清单必须全部对齐）。设置页新增「手机端发布」区域：发布签名密钥、发布向导、PR 状态与合并按钮。
- **发布必须由设备密钥签名**：每次发布都用手机 Keystore 里生成的 EC P-256 密钥签名，私钥不可导出；设备设置了锁屏时，签名前还需验证设备凭据。公钥登记在仓库中，CI 用它验签；签名同时绑定台账末条（旧签名无法重放）、数据库字节与版本说明——**即使 GitHub 令牌泄露也无法发布**。
- **GitHub App 登录**：可用 GitHub App 的设备流替代长期访问令牌。访问令牌约 8 小时有效并自动刷新，手机上只保留可轮换的刷新令牌；在 GitHub 卸载该 App 即可让所有设备一次性失效。已有的长期令牌仍可作为回退。
- **数据库版本唯一性门禁**：新增追加式台账 `database-versions.json`：版本号严格递增、sha1 唯一，`database-manifest.json` 是台账末条的投影。CI 在相关 PR、以及打 tag 构建前都会校验，发布后还会比对线上字节与台账是否一致。规则集已把 `Ledger, manifest and database agree` 设为 main 的必需检查。

## 修复

- 修复 GitHub App 设备流登录失败：申请设备码被误发到令牌端点，GitHub 返回 `incorrect_client_credentials`，界面显示成「Client ID 不正确」。
- 设备流出错时不再抛出无信息量的解析异常，改为显示中文说明、GitHub 原始错误码与响应片段。

## English

- **Publish the database from the phone.** The app reads the published ledger, takes
  the next version, stamps it into a copy of the local database, appends
  `database-versions.json`, re-projects `database-manifest.json`, and commits the
  three files on a publishing branch; CI only verifies (path allowlist, the version
  must be exactly the next one, and sha1/size/marker/manifest must all agree).
- **Every publication is signed by a device key.** A non-exportable EC P-256 key
  lives in the Android Keystore (user verification is required to sign when the
  device has a screen lock). CI verifies the signature against the public key
  registered in the repository, and the signed message binds the ledger tip
  (no replay), the database bytes and the release note — a leaked GitHub token can
  no longer publish anything.
- **GitHub App sign-in.** The device flow replaces the long-lived personal token:
  about eight-hour access tokens, refreshed automatically, with a rotating refresh
  token on the device that can be revoked for every device by uninstalling the app.
- **Database version uniqueness is enforced.** An append-only ledger, unique hashes,
  a manifest that is the projection of the ledger tip, a required status check, and
  a post-release comparison of the published bytes.
- **Fixes.** The device-flow login requested its device code from the token endpoint
  (GitHub answered `incorrect_client_credentials`, shown as "wrong Client ID") and
  errors are now reported with their real cause.
